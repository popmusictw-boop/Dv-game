# 北特教案生成系統

臺北市立臺北特殊教育學校「教學設計表」的教案製作系統。繁體中文介面，電腦、平板、手機皆可操作。

流程：**基本資料 → 上傳資料 → 確認先備能力 → 確認課綱 → 能力分組與目標 → 生成教案 → 編輯預覽 → 匯出（Word／PDF）**

## 快速開始（開發／試用）

```bash
pip install -r requirements.txt
python manage.py create-user teacher01 王老師 --admin   # 互動輸入密碼（至少10碼）
python app.py                                          # http://127.0.0.1:5000
```

正式部署（HTTPS、金鑰、OCR、PDF 轉檔）請見 [DEPLOY.md](DEPLOY.md)。

## 架構

| 部分 | 技術 | 說明 |
|---|---|---|
| 後端 | Python 3.11+、Flask、SQLite | `app.py`、`btsys/` |
| 前端 | 原生 HTML/CSS/JS（無建置步驟） | `static/`，響應式；CSP 限制只載入本站腳本 |
| 文字擷取 | pdfplumber、python-docx、Tesseract OCR（pypdfium2 轉影像） | `btsys/extract.py` |
| 分析 | 本機規則式（預設）；選用 Anthropic API | `btsys/analyze.py`、`btsys/ai.py` |
| 課綱 | 逐字擷取之 JSON ＋ 教師匯入 | `data/curriculum/`、`btsys/curriculum.py` |
| 匯出 | python-docx；LibreOffice 轉 PDF | `btsys/export_docx.py` |

## 課綱資料與來源

| 檔案 | 課綱 | 版本 | 筆數 | 來源 |
|---|---|---|---|---|
| `special_needs.json` | 十二年國民基本教育身心障礙相關之特殊需求領域課程綱要（9 科目：生活管理、社會技巧、學習策略、職業教育、溝通訓練、點字、定向行動、功能性動作訓練、輔助科技應用） | 108年7月 | 1,301（核心素養 153、學習表現 557、學習內容 591） | 國教院：https://stv.naer.edu.tw/data/course_outline/513721112.pdf |
| `service_group.json` | 十二年國民基本教育高級中等教育階段學校集中式特殊教育班服務群科課程綱要（群核心素養、專業科目 3、群必修實習 5、12 技能領域 32 科目、科別適用對照） | 110年4月 | 1,454（群核心素養 8、學習表現 220、學習內容 1,226） | 使用者提供之 PDF；國教院網站目前查得為108年7月版，**110年4月版官方連結待確認** |

- 每筆資料保存：代碼、原文、類型、科目、向度／主題、階段、版本、PDF 頁碼、來源連結。
- 擷取程式：`tools/parse_special.py`、`tools/parse_service.py`；核對程式：`tools/verify_curriculum.py`（學習表現、學習內容逐字比對 PDF 全文，**0 筆不符**）。核心素養來自 PDF 表格儲存格，已抽查。
- 代碼正規化：原文排版的「特社 1-II-1」「車技 I」統一記為「特社1-Ⅱ-1」「車技Ⅰ」，原印刷代碼另存於 `printedCode`。服務群核心素養原文無代碼，系統以「服務群核心素養一～八」作為索引，並於資料中註明。
- 教師調整敘述存在 `teacherText`，官方原文 `officialText` 不可修改（被改動時檢核會報錯），以 `itemId` 追溯。
- **未載入（一律顯示「待確認」，不以假資料替代）**：幼兒園教保活動課程大綱、國小／國中一般領域、技高一般科目、議題融入學習主題。可由「匯入正式課綱資料」以 CSV／JSON 匯入（必填 code、type、subject、text、version、sourceTitle），匯入資料標示「教師匯入」。

## 本校課程架構（聯動選單依據）

| 檔案 | 來源 | 用途 |
|---|---|---|
| `data/school/tpmr_115_service.json` | 115學年臺北市立臺北特殊教育學校集中式特教班服務群課程計畫（備查版） | 技高部科別（居家生活服務科、餐飲服務科）、各科部定／校訂科目、24 個校訂科目教學大綱（教學目標、單元、內容細項） |
| `data/school/tpmr_113_elem_jh.json` | 113學年度國小國中架構表 | 國小部、國中部的領域與各年級開設的特殊需求科目 |

- 技高部選科別後，只列出該科的部定科目、技能領域、校訂必修／選修與特殊需求科目。
- 校訂實習科目（如餐飲服務禮儀實作）沒有部定學習重點，系統自服務群科課綱推薦可對應項目，並標示「系統推估」；可從教學大綱直接選單元，內容細項作為推薦關鍵詞。
- 校訂一般科目（如地板滾球、繪本閱讀）對應之一般領域課綱尚未載入，顯示「待確認」，並列出教學大綱所載領域與核心素養項目名稱。
- 國小、國中依架構表：如國中溝通訓練只在七年級、職業教育只在九年級；本校架構未列的特殊需求科目另列為「依學生需求選用」。
- 課程計畫 PDF 的文字層欄位錯置，科目清單已依表 6-1-1／6-1-2 人工核對；教學大綱由 `tools/parse_school_plan.py` 擷取，16 個科目（多為選修實習）未在計畫中找到教學大綱，單元請自行輸入。

## 學生資料保護

- 須登入；每位教師只能存取自己的教案與檔案（他人存取回 404）。
- 上傳檔案、檔名、擷取文字、教案內容皆以 `BT_DATA_KEY`（Fernet）加密後保存；資料庫明文只有單元名稱與時間。
- 系統紀錄只記錄方法、路徑、狀態碼、使用者編號；稽核表只記錄動作與物件編號，不含學生姓名或內容。
- 可刪除單一檔案（同步移除以該檔為佐證的分析項目）、分析資料、學生、整份教案；`flask --app wsgi purge-old` 清除逾期資料（`BT_RETENTION_DAYS`）。
- 外部 AI 預設關閉。開啟需管理者設定 `BT_AI_ENABLED=1` 與伺服器端 `ANTHROPIC_API_KEY`，且教師每次勾選同意；送出前以代號取代姓名；AI 回傳的每句引用都回到原文逐字比對，比對不到即剔除。介面清楚標示目前為本機分析或 AI 分析。
- 上傳頁顯示資料處理位置、是否送出、OCR 狀態、保存期限與刪除方式。
- 安全標頭（CSP、nosniff、no-referrer、no-store）、CSRF 自訂標頭檢查、Session Cookie HttpOnly／SameSite／Secure。

## 「不虛構」的設計

- 能力描述＝上傳資料中的原句（標「原文事實」）＋檔名、頁碼／段落／句序。
- 與本單元的關聯、分組、目標、達成標準一律標「系統推估」或「建議值」。
- 資料中找不到的能力面向列「資料不足」，由教師補充；性別、障礙類別只在資料有明確欄位（如「性別：女」）時填入，不一致時標「資料矛盾」並留白。
- 掃描檔無法 OCR、格式不支援、辨識失敗時，明確告知且不產生內容；無資料的學生不能分析。
- 分組依支持需求（提示、示範、肢體協助等佐證）推估，不使用障礙類別或年級。
- 目標只依教師勾選的學習表現／學習內容產生；未勾選課綱時拒絕產生。

## 已完成與待串接

**已完成**：完整 8 步驟流程、登入與存取限制、加密保存、多檔多生上傳（PDF／Word／圖片／貼上文字）、OCR 流程、規則式擷取、選用 AI（含引文驗證）、課綱推薦／搜尋／檢核／匯入、分組、目標、教學活動（時間合計檢核）、草稿自動儲存與重新開啟、可編輯預覽、Word／PDF 匯出、列印、刪除功能、Docker 部署。

**待補／待串接**：

1. 原始範本已依原檔版面數值重建；原檔表格框線設定無法由 API 讀出，抬頭表比照內文表格加框，若原檔抬頭無框線請告知。另原檔「教學設計表」以 20pt 置於 106pt 寬欄位，伺服器轉 PDF 若無標楷體可能換行。
2. 原檔「學習重點」為單一儲存格；系統沿用原版型，在同一格內以「學習表現：」「學習內容：」分段呈現（系統內部三者分欄保存）。
3. 原檔抬頭為「□幼兒園□國小部□國中部█技高部部」，系統以「■技高部」呈現（去除重複的「部」）。
4. 幼兒園課綱、國中小一般領域、技高一般科目、議題融入：需匯入官方原文。
5. 繁體中文 OCR：伺服器需安裝 `tesseract-ocr-chi-tra`（Docker 映像已含）；本開發環境僅有英文辨識資料，中文 OCR 尚未以實際掃描檔驗證。
6. 外部 AI：需學校同意與 API 金鑰；未設定時系統不會送出任何資料。
7. 帳號：目前為系統內帳號（管理者以指令建立）；若要串接臺北市校園單一身分驗證，需取得 OIDC／SAML 介接資料。
8. 標楷體為商業字型：Word 檔指定標楷體，在 Windows 正常；伺服器轉 PDF 需放入學校授權的 `kaiu.ttf`，否則以楷書替代字型呈現。
9. 推薦排序為共同詞比對（系統推估），教師仍須逐項判斷。
